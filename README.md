# HazeGuard-KL

**大吉隆坡跨境烟霾 3 小时短临风险预警系统**

AIT201 Applied Machine Learning · 2026/09 · 小组项目

---

## 一句话说明

马来西亚环境部公布的 API 指数是 **24 小时滑动平均**，等它变红，空气早就脏了几个小时。
我们做一个能提前 **3 小时**给出 PM2.5 风险等级的系统，并告诉使用者这个判断有多不确定。

---

## 为什么做这个

大吉隆坡的 PM2.5 有两种来源叠在一起：

- **本地日周期**：早晚高峰的机动车排放，每天重复，其实不难预测；
- **跨境烟霾**：每年 6–9 月西南季风把苏门答腊、加里曼丹的生物质燃烧烟霾吹过马六甲海峡，
  几个小时内就能把 PM2.5 从 20 µg/m³ 推到 100 以上。

真正会停课、取消户外活动、把哮喘病人送进急诊的是第二种。而官方指数因为要做 24 小时平均，
天然滞后于这种脉冲式恶化。举例：下午 14 点烟霾到达，PM2.5 从 25 涨到 95，
对 24 小时均值只贡献 70 µg/m³ 的增量，摊到大部分是干净空气的分母上，指数要几个小时才"反应过来"。

所以我们认为，缺的不是"现在有多脏"，而是**"三小时后会有多脏，以及这个判断有多不稳"**。

---

## 我们要做的东西

**输入**：某站点过去若干小时的逐小时观测（污染物 + 气象）。
**输出**：

1. `target_pm25_3h` — 三小时后的 PM2.5 浓度（回归）
2. `target_level_3h` — 三小时后的四级风险等级（**有序**分类）
3. 90% 预测区间 + 一条"这次预警靠不靠得住"的解释

**四级风险划分**（单位 µg/m³）：

| 等级 | 区间 | 含义 | 建议 |
|---|---|---|---|
| Level 0 | [0, 15) | 良好 | 正常活动 |
| Level 1 | [15, 35) | 中等 | 敏感人群减少长时间户外 |
| Level 2 | [35, 55) | 高 | 减少户外，关窗 |
| Level 3 | ≥ 55 | 极高危 | 避免户外，戴 N95 |

这四个等级是**有顺序**的（0 < 1 < 2 < 3），而且判错的方向代价完全不同——
把"极高危"报成"中等"和反过来，后果不是一个量级。这是本项目所有模型设计的出发点。

## 数据

### 来源

| 数据 | 接口 | 分辨率 | 变量 |
|---|---|---|---|
| 空气质量 | Open-Meteo `air-quality-api`（CAMS 全球大气成分产品） | 0.4°（约 45 km） | PM2.5、PM10、NO₂、SO₂、O₃、CO |
| 气象 | Open-Meteo `archive-api`（ERA5 再分析） | 约 9 km | 气温、相对湿度、风速、风向、降水 |

时间范围 **2022-08-01 → 2026-10-31**（51 个月，逐小时），时区 `Asia/Kuala_Lumpur`。
两个接口都免费、无需密钥，任何人 clone 下来都能重跑。

### 空间单元：26 个格点，不是 26 个监测站

这一点我们踩过坑，写在这里免得别人误解。

原计划按"大吉隆坡 8 个监测站"来做。实际拉下来发现：**8 个点位只落在 3 个 CAMS 格点上，
同格点内的小时序列逐位完全相同**。因为 45 km 的格距比整个巴生谷（约 40 km）还大。

这意味着如果硬做 8 个站：

- 上风向传导特征失效——所谓"邻居站点"就是它自己；
- 留一站点验证（LOSO）退化——留掉一个站，同格的兄弟还带着一模一样的数据。

所以我们改了做法：撒 33 个候选点，按"序列是否完全相同"去重，得到 **26 个真正互异的格点**，
并向西延伸到苏门答腊、向南延伸到加里曼丹的火点区。这不只是凑数量——
跨境烟霾本来就是几百公里尺度的事件，格点尺度恰好合适。

见 `docs/node_discovery.json`（去重的原始证据）和 `tools/discover_nodes.py`。

| 角色 | 数量 | 用途 | 节点 |
|---|---|---|---|
| **受体 Receptor** | 3 | 预测目标，KL 部署站点 | KL_City、Port_Klang、Sepang |
| **走廊 Corridor** | 10 | 既是目标也是上风向源 | 半岛各城（Seremban、Malacca、Johor Bahru、Kuantan、Temerloh、Kota Bharu、Kuala Terengganu、Penang、Alor Setar、Ipoh） |
| **源区 Source** | 13 | 仅作上风向特征输入 | 苏门答腊 8（Banda_Aceh…Bengkulu）+ 加里曼丹 5（Pontianak…Bintulu） |

气象数据在每个点位都不同（ERA5 网格更细），所以上风向风矢量特征是有信息量的。

### 数据规模

- **966,677 行 × 35 列**，`data/haze_panel_clean.parquet`（25 MB）
- 切分：train 676,884 / val 145,054 / test 144,739（逐节点按时间 70/15/15，**绝不 shuffle**）
- 全部字段口径见 `data/data_dictionary.json`，完整性清单见 `data/manifest.json`

### 测试集里有一次真实的烟霾事件

2026 年 8–10 月，`KL_City` 单月 Level 3 占比达 **46.9% / 51.0%**，PM2.5 的 95 分位是 **151.8 µg/m³**。

这对我们是好事：高危召回率是在真实事件上测出来的，不是在背景噪声上。
但它也意味着**测试集比训练集更难**（Level 3：18.85% vs 11.13%），
所以别拿我们的测试数字去和别人的同分布结果直接比。

## 方法：一个不学习的对手 + 七个模型，一条评估口径

模型矩阵的排序不是按新旧，而是按"它回答哪个问题"。每一行都有一个明确的对照对象。

| 编号 | 模型 | 范式 | 为什么要有它 | 负责人 | 课程位置 |
|---|---|---|---|---|---|
| M0 | Persistence | 规则 | **不学习的对手**：直接把当前等级当三小时后。树干不过它就没意义 | 1号 | — |
| M1 | Decision Tree | 多分类 | 地板线。证明后面的复杂度不是白加的 | 1号 | W6 |
| M2 | Nominal RF | 多分类 | 完全不管等级顺序的对照 | 4号 | W7 |
| M3 | Balanced RF | 多分类 + 类权重 | `class_weight='balanced_subsample'`，看权重能救多少 | 4号 | W7 |
| M4 | Boosting | 集成-提升 | 提升法在表格数据上常常最强。**如果它赢了 RF，我们就如实报** | 4号 | W7 |
| M5 | Reg-to-Cls RF | 回归 → 阈值切档 | 用回归**隐式**保序，是 M6 的课内对照 | 5号 | W2 / W7 |
| M6 | Ordinal RF | 累积二分类分解 | **显式**建模等级次序。全项目唯一保留的课程外方法，见 `docs/syllabus_coverage.md` | 5号 | 需论证 |
| M7 | Cost-Sensitive Ordinal RF | 有序 + 非对称代价 | 在验证集上网格搜索判定阈值 τ，直接压低漏报 | 6号 | W4 |

**为什么 M5 和 M6 要并排放**：它们解决同一个问题——"四个等级是有顺序的"——但走两条路。
M5 把顺序交给回归的连续性，M6 把顺序写进三个累积二分类。哪个更好不是先验能定的，
必须用 MAOE 与跨级误判率实测。**这也是本项目的核心对照实验**。

**统一评估的六项指标**（全部由 `src/utils_metrics.py` 产出，谁都不许自己另写一套）：

| 指标 | 定义 | 方向 |
|---|---|---|
| Macro_F1 | 四等级 F1 的算术平均 | ↑ |
| Balanced_Accuracy | 各类召回率的平均 | ↑ |
| **High_Risk_Recall** | 真实高危(L2∪L3)中，预测落在 {L2,L3} 的比例（**核心防漏报**；问的是有没有拉警报，不是等级报没报对） | ↑ |
| MAOE | 平均绝对序差 (1/N)Σ\|y−ŷ\| | ↓ |
| Severe_Jumping_Error_Rate | 跨两级误判比例 (1/N)Σ1(\|y−ŷ\|≥2) | ↓ |
| Avg_Asymmetric_Cost | 平均非对称代价 (1/N)ΣC[y][ŷ] | ↓ |

另外报一条**高危二分类的 ROC / AUC**（Level 2∪3 视为正类）。它不是模型，是把阈值选择
画成一条可看的曲线：AUC 说明"排序能力"，工作点说明"我们愿意在哪个误报率上换多少召回"。

**非对称代价矩阵** `C[i][j]` = 真实为 i、预测为 j 的代价：

```
         预测 L0  L1  L2  L3
真实 L0  [   0    1   3   5 ]
     L1  [   2    0   1   3 ]
     L2  [   8    4   0   1 ]
     L3  [  15   10   5   0 ]
```

左下角（漏报高危）是普通误报的 8–15 倍。理由很直白：把一个危险的日子报成"中等"，
人会照常出门；把"中等"报成"危险"，最多是白防了一次。

## 快速开始

```bash
git clone https://github.com/baiyizhuoait/HazeGuard-KL.git
cd HazeGuard-KL

conda create -n hzkl python=3.11 -y
conda activate hzkl
pip install -r requirements.txt

python src/01_verify_data.py       # 先校验数据完整性，应 11/11 通过
python src/01_data_pipeline.py     # 采集+清洗+切分+基线（首次约 3 分钟）
python src/01_baseline_dt.py       # M1 基线（约 10 秒）
```

### Agent 2 独立运行与成员 3 入口

Agent 2 以现有 `data/haze_panel_clean.parquet` 为只读输入，输出 966,677 行 × 91 列，完整保留原 35 列。新增 56 列中，50 列是预测输入，6 列是离线审计标记。当前数据含 26 个 CAMS 格点、3 个受体，不能当作原规范的八个独立实测站。

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r requirements-agent2.txt
git lfs pull  # 克隆仓库时获取大文件；完整交付 ZIP 已含实体数据
python src/02_spatiotemporal_features.py
python src/02_eda_analysis.py
python tools/verify_agent2.py
```

无需重新抓取 API，也无需 Git 目录即可从完整 ZIP 重跑。普通 GitHub 源码 ZIP 的 parquet 可能只是 LFS 指针，不能将其视为完整数据；缺少 LFS 工具时，从上述真实清洗数据运行两个 `02_*.py` 即可重建。特征与五图均有 SHA256 和实际运行统计，见 `models/metrics_stage2_*.json`。

成员 3 读取 `data/feat_spatiotemporal.parquet`，只按 `models/metrics_stage2_features.json` 的 `model_feature_columns` 取预测列。`agent2_*` 包含未来标签核对结果，只能用于离线样本审计，不能输入模型或控制线上发出预测。主训练域仍为 `role == 'receptor'`，训练折内处理缺失值并重新拟合所有学习型变换。完整示例和数据限制见 [02 交接文档](docs/handover/02_eda_and_spatiotemporal.md)。

四个风险等级是项目实验分组，不是官方小时级 AQI 健康标准。上风向特征描述方向加权统计关系，不能单独证明跨境污染传输。

`01_data_pipeline.py` 会把 API 响应缓存到 `data/raw/`，第二次跑秒出。
加 `--force-refresh` 可强制重新拉取。

## 目前的结果

test 段，受体节点 n = 16,728（其中真实高危 6,865）：

| 指标 | **M0 纯持续性** | **M1 决策树** | M1 − M0 |
|---|---|---|---|
| Macro_F1 | 0.6222 | **0.6620** | +0.0398 |
| Balanced_Accuracy | 0.6222 | **0.6443** | +0.0221 |
| **High_Risk_Recall** | **0.7752** | 0.7693 | **−0.0059** |
| MAOE | 0.3930 | **0.3220** | −0.0710 |
| Severe_Jumping_Error_Rate | 0.0375 | **0.0218** | −0.0157 |
| Avg_Asymmetric_Cost | 0.9986 | **0.8905** | −0.1081 |

M1 超参 `gini / max_depth=9 / min_samples_leaf=20`，384 个叶子，训练-验证 gap 只有 0.015（没过拟合）。
M0 没有任何学习：直接把 t 时刻的等级当成 t+3h 的等级。

**`High_Risk_Recall` 的口径**：真实高危（L2∪L3）样本中，预测落在 {L2, L3} 的比例——
问的是"高危有没有被预警"，不是"等级有没有报对"。真实 L2 报成 L3 属于过度预警，不算漏报。
两种口径差别很大（M1：union 0.7693 vs 逐类 0.5707），所以报告里必须写明用的是哪一种。

**我们从这个对照里读出的三件事：**

1. **M1 在综合指标上赢了，但在最要命的那个指标上输了。**
   Macro-F1 +0.04、MAOE −18%、代价 −11%，看起来全面占优；
   可**高危召回 0.7693 比纯持续性 0.7752 还低**。换句话说，我们训了一棵树，
   在"该不该拉警报"这件事上反而不如"照着昨天的天气抄"。
2. **原因是它在边界处系统性向下保守。** 1,348 个真实 L2 被判成 L1、758 个真实 L3 被判成 L2，
   反方向误报只有 9 例。树为了迁就占约 50% 的 L1，把边界整体往下压了。
   **这正是 M6（有序分解）和 M7（代价敏感阈值）要解决的东西，也是本项目的立项依据。**
3. **不同站点表现不一致，而且有物理原因。** `Port_Klang` 的 Macro-F1 最高但高危召回最低，
   因为它本身最干净（Level 3 只占 1.9%），少数类在训练里见得最少。

> 如果只报 Macro-F1，这个项目看起来"树比持续性略好"；把高危召回单列出来，
> 才看出真正的差距。这也是我们把 `High_Risk_Recall` 放在六项指标第三位、并写入 CV 讨论的原因。

## 已知局限

我们尽量写清楚，而不是藏在结论里。

1. **空气质量是模式产品，不是监测站实测。** CAMS 全球产品的格距约 45 km，
   适合研究区域输送，不适合谈街道级暴露。报告里不会出现"measured at station"这种说法。
2. **存在系统性正偏。** `KL_City` 两年均值约 41 µg/m³，明显高于马来西亚官方常年水平。
   跨数据源比较时要注意。
3. **时间分辨率偏平滑。** 我们检查过是否是被 3 小时原生数据线性插值出来的
   （二阶差分近零的比例只有 0.6%，不存在 3 小时分段线性结构），所以不是插值痕迹，
   但模式产品本身比真实站点平滑，滞后 1 小时的自相关会偏强。
4. **部分数据有已知缺陷**，已用标记列标出而不是偷偷修掉：
   - `qc_pm25_gt_pm10`：303 行 PM2.5 > PM10（物理上不可能）；
   - `qc_censored`：4 行贴着 900 µg/m³ 的输出上限，是被截断的，不能当真实极值；
   - `qc_calm_wind`：5% 的时段风速 < 0.5 m/s，此时风向是噪声；
   - 源区 `Palangkaraya` 有 37 小时真实缺口，我们没插值——补上等于编造一次烟霾过程。
5. **样本不均衡的方向和一般文献相反。** 这里的 Level 3 占 12%，并不稀有；
   真正少的是 Level 0（17.9%）。所以我们不说"严重不平衡"，而是说代价不对称。
